# 株スクリーニング条件メーカー

3つの質問に答えると、みんかぶの銘柄スクリーニング(条件検索)にそのまま渡せるURLを組み立てるWebアプリ。
HAKONIWA LAB の10本目のツール。ビルドツール不要の Vanilla HTML/CSS/JS。

公開URL: https://hakoniwa-lab.github.io/stock-screener/

## 何を解いているのか

スクリーニング自体は無料で誰でも使えるのに、**入れる数字が分からないから使えない**、
というのが初心者の実際の壁。「PERって何？いくつ入れればいいの？」を埋めるのがこのアプリの役目。

## ⚠ 設計上の絶対条件 — データを持たない

**株価データを取得・保存・表示してはいけない。** 条件を組み立ててURLを渡すだけに留める。

これは実装が楽だからではなく、**みんかぶ利用規約に抵触しないための条件**。

- 第7条(18) 「本サイト公認以外の方法による、プログラム、スクレイピング等により本サイトのコンテンツを機械的に取得する行為」
- 第7条(19) 「本サイトのコンテンツを私的使用の範囲を超えて蓄積する行為」

現状の作りはどちらにも該当しない(何も取得せず、何も保存しない)。
外部サイトから みんかぶ へのリンク設置を制限する条文は無いことも確認済み(2026-08-15)。
**将来「結果をこのページに表示する」方向へ拡張すると規約違反になる。** そこは越えないこと。

## 数値の根拠

投資系YouTube 8チャンネル・439本の自動字幕を取得し、本文中に登場する指標の数値を
正規表現で全件抽出して中央値を取ったもの(2026-08-14集計)。
元データと集計手順は `projects/指定の株について調べる/knowledge.md` を参照。

| 指標 | 配当狙い | 値上がり狙い |
|---|---|---|
| PER | 9.9倍 | 18.2倍 |
| PBR | 1.0倍 | 1.0倍 |
| 配当利回り | 4.2% | 3.0% |
| 配当性向 | 40% | — |

**自動字幕は固有名詞(銘柄名・企業名)を高頻度で誤変換する**(半導体→反動体、キオクシア→記憶シア等)。
指標名と数値は正しく出るため集計に使えるが、**銘柄名をこのデータから拾ってはいけない**。

## 3つのモード(実機検証済み・時価総額300億円以上の場合)

| モード | 条件 | ヒット数 |
|---|---|---|
| 配当でコツコツ | PER≤10 / 利回り≥4.2% / 配当性向≤40% | 36件 |
| 値上がり狙い | PER≤18 / 3年平均売上成長≥10% / 営業利益率≥10% | 108件 |
| 株主優待 | 優待あり / 利回り≥2.4% / PER≤16 / EPS>0 | 296件 |

優待モードは当初PER条件なしで439件と広すぎたため、優待勢のPER中央値16.1倍を追加して絞った。

## みんかぶスクリーナーのパラメータ(2026-08-15 検証済み)

すべて `[0]`=下限 `[1]`=上限。`min` / `max` が使える。

| パラメータ | 意味 | 単位 |
|---|---|---|
| `per` `pbr` | PER / PBR | 倍 |
| `dividend_yield` | 配当利回り | % |
| `payout_ratio` | 配当性向 | % |
| `market_capitalization` | 時価総額 | **億円** |
| `minimum_purchase_price` | 最低投資金額 | **万円** |
| `capital_adequacy_ratio` | 自己資本比率 | % |
| `roe` `roa` | ROE / ROA | % |
| `sales_cagr_3y` | 3年平均売上高成長率 | % |
| `operating_income_margin` | 売上高営業利益率 | % |
| `consecutive_increased_dividend_count` | 連続増配年数 | 年 |
| `eps` | 1株あたり利益 | 円 |
| `yutai_exist=1` | 優待あり | 配列でなく単値 |

加えて `view=result` `page=1` `sort_key=<上記いずれか>` `order=desc|asc` が必要。

**みんかぶ側の仕様が変わると壊れる。** 動かなくなったら `https://minkabu.jp/stock/search` を開き、
「おすすめ条件」のリンクURLを読んでパラメータを取り直す。

## UI上の判断

- **結果リンクは `target="minkabu-result"`**(`_blank` ではない)。名前付きにすることで、
  条件を変えて何度押しても結果タブが1つに保たれる。`_blank` だと押すたびタブが増えて実用に耐えない。
- **Q2で「大きさを問わない」を選ぶと警告を出す。** 104件→3件という実測に基づき、
  「小型株に偏ること」「安いのには流動性が低いという理由があること」を明示する。
- **連続増配5年以上のチェック時にも警告。** 0件になりやすいため。

## 収益化

- **AdSense**: **初版では意図的にタグを外している**(2026-08-15)。
  AdSenseが低品質コンテンツで一度却下され再審査中の状況で、金融はYMYL領域として
  審査が特に厳しいため、審査が通るまで広告コードを入れない判断。
  `index.html` の `<head>` にコメントで復活手順を残してある。
  審査通過後、そのタグを戻し `#ad-slot-result-bottom`(結果カードの下)に広告ユニットを差し込む。
  なお広告を入れる入れないに関わらず、投資助言に見えない建て付け
  (「おすすめ銘柄」ではなく「検索条件を作るだけ」)は必ず維持すること。
- **クロスリンク**: takehome-calculator / sidejob-tax-simulator / furusato-simulator へ送客。
- A8のネット証券案件は未接続。入れる場合も、**銘柄推奨と誤読されない位置**に置くこと。
